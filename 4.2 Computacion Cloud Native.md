# Computacion Cloud Native

Cloud Native (o nativo de la nube) es un enfoque para diseñar, construir y ejecutar aplicaciones aprovechando completamente la computación en la nube.

No significa solo poner una app en un servidor cloud, sino crear aplicaciones pensadas desde el inicio para ser escalables, resilientes y automatizadas.

El término es promovido por la Cloud Native Computing Foundation (CNCF), que define el ecosistema de tecnologías como contenedores, microservicios, orquestación y automatización.


## Principios clave

Tenemos algunos principios clave como:

- **Microservices Architecture:** Dividir las aplicaciones en servicios pequeños, independientes y débilmente acoplados para permitir el desarrollo modular y la escalabilidad.
- **Containerization & Orchestration:** Empaquetar las aplicaciones y sus dependencias en contenedores (como Docker) y utilizar herramientas como Kubernetes para automatizar la implementación y la gestión.
- **Automation (DevOps, CI/CD, IaC):** Utilizar pipelines de CI/CD para la automatización de pruebas y despliegues, e infraestructura como código (IaC) para gestionar recursos en minutos, reduciendo los errores manuales.
- **Immutable Infrastructure:** Tratar la infraestructura como reemplazable en lugar de actualizable; en vez de aplicar parches, los servidores se reemplazan por otros nuevos y actualizados.
- **Managed Services:** Aprovechar las bases de datos, la mensajería y las opciones sin servidor gestionadas por el proveedor para delegar la gestión de la infraestructura.
- **Observability & Monitoring:** Using robust logging, metrics, and tracing to understand system behavior and troubleshoot issues quickly.
- **Resilience & Fault Tolerance:** Diseñar sistemas que prevean y gestionen adecuadamente los fallos de los componentes, garantizando una alta disponibilidad.
- **Security by Design:** Implementar la seguridad en todo el ciclo de vida del desarrollo, incluyendo la defensa en profundidad (confianza mínima entre componentes).
- **Statelessness:** Diseñar servicios que no almacenen datos localmente, lo que permite reemplazarlos o escalarlos sin perder la integridad de los datos.

## Arquitecturas

### Arquitectura Monolitica

En arquitectura de software, un monolito (arquitectura monolítica) es un tipo de aplicación donde todo el sistema está construido como una sola unidad grande.

#### Características

- **Un solo despliegue:** Si cambias una pequeña parte del sistema, debes volver a desplegar toda la aplicación.
- **Una sola base de código:** Todo vive en el mismo repositorio o proyecto.
- **Escalado completo:** Si solo el módulo de pagos necesita más capacidad, igual debes escalar toda la aplicación.
- **Alta dependencia interna:** Los módulos dependen mucho entre sí.

### Arquitectura Microservicios

La arquitectura basada en microservicios es un estilo de arquitectura de software donde una aplicación se construye como un conjunto de servicios pequeños, independientes y especializados, que se comunican entre sí mediante APIs.

Cada microservicio resuelve una función específica del negocio y puede desarrollarse, desplegarse y escalarse de forma independiente.

#### Características

- **Escalabilidad independiente:** Solo escalas el servicio que necesita más recursos.
- **Despliegue independiente:** Puedes actualizar un servicio sin afectar a los demás.
- **Equipos independientes:** Cada equipo puede trabajar en diferentes servicios.
- **Mayor resiliencia:** Si un servicio falla, los demás pueden seguir funcionando.

### Serverless

Serverless Computing es un modelo de computación en la nube donde el desarrollador no administra servidores.

El proveedor cloud se encarga de aprovisionar, escalar, ejecutar y apagar la infraestructura automáticamente.

El desarrollador solo escribe funciones o código que se ejecuta cuando ocurre un evento.

Soluciones FaaS en nubes publicas: AWS Lambda, Azure functions, Google Cloud functions

#### Características

- No administras servidores
- Escalado automático
- Pago por uso
- Ideal para aplicaciones event-driven

## Serverless en Kubernetes

### Knative

Knative es una plataforma serverless para Kubernetes que permite ejecutar aplicaciones basadas en eventos y funciones sin tener que administrar directamente los detalles de infraestructura.

Componentes principales de Knative

- **Knative Serving:** Permite desplegar aplicaciones serverless sobre Kubernetes.
- **Knative Eventing:** Permite construir arquitecturas basadas en eventos.
- **Knative Functions:** Permite ejecutar funciones serverless de forma más sencilla.

### OpenFaas

OpenFaaS (Open Functions as a Service) es una plataforma serverless open source que permite ejecutar funciones en contenedores, normalmente sobre Kubernetes o Docker Swarm.

Su objetivo es permitir que los desarrolladores ejecuten funciones tipo serverless (como AWS Lambda) pero en su propia infraestructura.

Puedes escribir servicios y funciones en varios lenguajes como: Python, Go, Node.js, Java, PHP, Ruby y C#.

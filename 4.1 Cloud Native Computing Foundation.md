# Cloud Native Computing Foundation (CNCF)

La Cloud Native Computing Foundation (CNCF) es una organización de código abierto bajo la Linux Foundation que acelera la adopción de tecnologías "Cloud Native", es decir, aplicaciones diseñadas para la nube usando contenedores, microservicios y orquestadores como Kubernetes (CNCF alberga a Kubernetes). Su función es unir desarrolladores, usuarios y proveedores para crear estándares, fomentar la colaboración y apoyar proyectos críticos que hacen posible construir sistemas escalables, resilientes y manejables en la nube. 

## ¿Qué es la CNCF?

- __Organización neutral:__ Es una entidad independiente de proveedores que apoya la evolución de la computación nativa en la nube.
- __Parte de la Linux Foundation:__ Opera como un proyecto dentro de la Linux Foundation.
- __Promueve estándares:__ Establece y promueve tecnologías clave como Kubernetes, Envoy y Prometheus.

## ¿Qué hace la CNCF?

- __Aloja proyectos:__ Gestiona el ciclo de vida de proyectos de código abierto (Sandbox, Incubating, Graduated), desde su inicio hasta su madurez en producción.
- __Crea comunidad:__ Organiza eventos (como KubeCon) y fomenta la colaboración entre desarrolladores, empresas y usuarios finales.
- __Asegura interoperabilidad:__ Trabaja para que las diferentes herramientas nativas de la nube funcionen bien juntas.

## El CNCF Landscape

El CNCF Landscape es un mapa visual interactivo creado por la Cloud Native Computing Foundation (CNCF) que organiza y categoriza el vasto ecosistema de proyectos y productos de computación nativa en la nube, sirviendo como una guía para navegar entre tecnologías de orquestación, almacenamiento, seguridad, observabilidad y más, para construir aplicaciones escalables y resilientes en la nube. 

https://landscape.cncf.io/

## Comunidad abierta

La CNCF se basa en una comunidad abierta donde pueden participar: desarrolladores, empresas, usuarios, maintainers.
Se da el desarrollo colaborativo, intercambio de conocimientos e innovación

## Gobernanza

Cada proyecto dentro de la CNCF tiene su propio equipo de gobierno, normalmente compuesto por:

### Maintainers

Responsables de:

- revisar código
- aceptar contribuciones
- mantener el proyecto

### Committers

- Desarrolladores con permisos para hacer cambios en el repositorio.

### Contributors
- Personas que contribuyen con:
- código
- documentación
- pruebas
- mejoras.

## CNCF Committees and Groups

Los Committees and Groups son equipos que ayudan a organizar, gobernar y desarrollar el ecosistema cloud native. Cada grupo tiene responsabilidades específicas dentro de la comunidad.

- **Technical Oversight Committee (TOC):** El CNCF Technical Oversight Committee es el comité técnico principal.

  Funciones:

  - Supervisar la dirección técnica de la CNCF
  - Evaluar nuevos proyectos
  - Decidir si un proyecto entra a la CNCF
  - Determinar el nivel de madurez de los proyectos (Sandbox, Incubating, Graduated)

- **Governing Board (GB):** El CNCF Governing Board es el órgano que toma decisiones estratégicas y de negocio.

  Funciones:

  - Dirección estratégica de la fundación
  - Gestión financiera
  - Membresías de empresas
  - Crecimiento del ecosistema

- **Technical Oversight Committee (TOC):** El CNCF Technical Oversight Committee es el comité técnico principal.

  Funciones:
  
  - Supervisar la dirección técnica de la CNCF
  - Evaluar nuevos proyectos
  - Decidir si un proyecto entra a la CNCF
  - Determinar el nivel de madurez de los proyectos (Sandbox, Incubating, Graduated)


- **TAGs (Technical Advisory Groups):** Los Technical Advisory Groups asesoran técnicamente a la CNCF en áreas específicas.

  Ejemplos de TAGs:
  
  - TAG Security
  - TAG Runtime
  - TAG Storage
  - TAG Network
  
  Estos grupos analizan tecnologías y ayudan a evaluar nuevos proyectos.

- **Working Groups:** Los Working Groups son grupos temporales que trabajan en problemas o iniciativas específicas.

  Por ejemplo:
  
  - Mejorar estándares
  - Crear documentación
  - Desarrollar nuevas iniciativas.

## Resolución de conflictos

La resolución de conflictos (Conflict Resolution) dentro de la Cloud Native Computing Foundation sigue un proceso estructurado para manejar desacuerdos dentro de la comunidad y los proyectos open source.

Proceso:

1. Discusión entre contribuyentes
2. Intervención de maintainers
3. Escalación a líderes del proyecto
4. Escalación al TOC
5. Intervención del Code of Conduct Committee si es necesario

## Estandares abiertos

La CNCF participa en la creación, mantenimiento o promoción de varios estándares abiertos del ecosistema cloud-native. Muchos de ellos son interfaces que permiten que diferentes herramientas funcionen juntas.

- Open Container Initiative (OCI)

  - Define estándares para imágenes de contenedores y runtimes.
  - Ejemplo: formato de imágenes usado por Docker y Kubernetes.

- Container Runtime Interface (CRI)

  - Interfaz que permite a Kubernetes comunicarse con diferentes container runtimes.
  - Ejemplos de runtimes: containerd o CRI-O.
 
- Container Network Interface (CNI)

  - Estándar para conectar contenedores a redes.
  - Permite usar diferentes plugins de red.

- Container Storage Interface (CSI)

  - Estándar para integrar sistemas de almacenamiento con Kubernetes.
  - Permite usar discos cloud o sistemas distribuidos.

- Service Mesh Interface (SMI)

  - Estándar para integrar un service mesh con Kubernetes
  - Ejemplos: Istio, Linkerd, Consul

- OpenTelemetry

  - Estándar abierto para observabilidad.
  - Permite recolectar: métricas, logs, trazas

- Gateway API

  - Estándar moderno para gestionar tráfico y networking en Kubernetes.
  - Evolución del recurso Ingress.
